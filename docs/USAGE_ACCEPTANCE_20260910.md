# 按实际使用验收

2026-09-10 起，项目以开机登录后的实际交付为主要运行验收。用户无需在固定时刻开机，也无需连续使用五天。原有美东 09:00 晨报保留为可选能力，历史结果不改写。

## 分开观察四件事

1. **交付完整性**：六个货币对齐全，输入覆盖生成日或前一 FX 工作日；实际观察时间、稿件日期与发布顺序有效；输入快照可读且哈希一致；稿件引用的包与保存包完全相符；推送回执指向同一稿件。
2. **自动化来源**：原始生成与发布有相匹配的自动调用证据。后来的定时“已有稿件”检查不能倒推原始生成来源。没有旧调用记录的稿件仍可核对交付，自动化一栏明确显示未证实。
3. **新闻覆盖**：单独记录通过规则检查的解读数、请求失败及数字版降级。某一条通过检查不表示所有货币都有完整解读，更不证明新闻因果解释正确。
4. **公开可见性**：本地回执只证明推送流程返回成功。公网构建和稿件哈希需要另外读取网站验证。

## 状态含义

| 状态 | 含义 |
| --- | --- |
| 尚无实际使用记录 | 没有可用调用或稿件证据，不判故障，也不推断电脑是否开机 |
| 等待可用输入 | 实际检查已运行，归因或新闻暂不齐备 |
| 完成情况待确认 | 有开始或进行中记录，缺少完整结束证据 |
| 实际运行需要检查 | 执行失败、档案损坏或交付校验不通过 |
| 已核对交付 | 保存的输入、稿件、日期和推送回执检查通过；自动化来源与新闻质量另列 |

报告累计实际观察日和已核对交付日，不计算固定目标天数或将中间缺少记录的日期补作失败。最近一条已交付记录不表示电脑现在在线，也不代表连续无故障；始终同时显示记录日期。

## 调度与证据边界

本次没有改动模型、参数、冻结归因、任务触发时间、调用预算或原有稿件。登录后两分钟和每十五分钟的补发检查继续使用，现有工作日 09:05 美东之后的时间门限也保持原样。它是任务安排，不是验收截止。数据没有追上时继续等待，无法承诺登录后两分钟就完成交付。

补发新增逐次起止调用记录，保留原始 source、时间和对应稿件哈希。旧的 status.json 会随检查更新，因此它单独不能证明旧稿的自动生成过程。不得为使验收通过而回填或改写旧证据。

9 月 12 日的兼容完善还会读取与稿件输入哈希对应的旧草稿，从中识别早期 `GenerationError`。旧稿没有新版失败标记时，也不会把已记录的失败遗漏。草稿不匹配或无法读取时单独提示，不能借用另一份草稿断言这份报告失败。内容被拒绝与请求生成失败分别统计。

```powershell
python -m fxdash.narrative.usage_acceptance --start-date 2026-09-08
python -m fxdash.operations
```

第一个命令只读并打印结果。第二个命令追加本地 JSON/HTML 观察快照并刷新 latest.html，不抓新闻、不调用模型、不发布。原来的 `fxdash.narrative.acceptance` 保持为可选固定时段诊断。
